# Project Review — 2026-10-03

A full read of the repository plus a live run of the real stack. This
documents what I verified working, what I found broken, what I fixed, and
what I could not verify from this sandbox. Written to be checkable — every
claim below names the command or test that produced it.

---

## 1. What this project is (as I understand it)

An enterprise financial-document RAG platform over three SEC filings
(Apple / Meta / Tesla, Q4 2023). Its actual thesis is not "answer
questions" — it is **provable answers**: every certified claim carries a
cryptographic receipt (claim → citation → evidence span → page transcript
→ SHA-256 → source PDF anchor) that an outsider can re-verify offline with
zero trust in the system.

Layers:

| Layer | File | Role |
|---|---|---|
| Ingestion | `ingest.py` (1,021 ln) | PDF → chunks + byte-exact page transcripts, manifest-driven, atomic |
| Persistence | `db.py` (2,023 ln) | pgvector hybrid search, RLS tenancy, semantic cache, receipts, ADR-017 fact store |
| Orchestration | `adaptive_rag.py` (3,732 ln) | LangGraph: cache → router → premise gate → specialist fleet → cross-check → synthesis → 5 deterministic gates → LLM audit → receipt |
| Serving | `main.py` (848 ln) | FastAPI: auth, rate limit, disconnect guard, SSE, /verify, /export, metrics |
| Console | `frontend/` (React 19 + Vite) | live pipeline rail, per-claim verifier badges, receipt explorer |
| Fact store (V2) | `fact_extract.py`, `fact_templates.py`, `fact_shadow.py` | ADR-017: numbers are *looked up*, not generated; Path A measured in shadow, never served |

The engineering culture in the docs is unusually disciplined: a 22-class
regression ledger, fail-closed-by-default posture, and an explicit rule
that refusals must name their **true** cause. Both bugs I found below are
violations of rules the project had already written down for itself.

## 3. Bug #1 — FIXED: `/query/stream` ran as the wrong tenant

**Severity: high (cross-tenant data exposure on the path the console uses).**

```python
# main.py, before
tenant = _resolve_scoped_tenant(auth_tenant, tenant_id)   # correct
return StreamingResponse(
    _event_stream(request, question, tenant_id, run_id),  # <-- RAW param
```

`_event_stream` re-resolves the tenant with `_resolve_tenant(tenant_id)`.
Passing the raw value means: **an authenticated key bound to `acme` that
simply omitted `tenant_id` ran the entire pipeline as `default`** —
retrieval, RLS scope, and the tenant stamped on the receipt.

`POST /query` always forwarded the resolved value, so the two entry points
silently disagreed — and SSE is the endpoint the React console uses.

Proof (test written before the fix):

```
AssertionError: LEAK: authenticated acme ran as 'default'
assert 'default' == 'acme'
```

Fix: forward the resolved tenant. Locked by two regression tests in
`tests/test_main.py` (`test_sse_authenticated_key_without_declaration_
uses_key_tenant`, `test_stream_and_post_agree_on_resolved_tenant`) — both
fail on the old code, both pass now.

> Note: the *anonymous* spoofing cases were already covered by the Phase-1
> tenancy tests. The gap was the **omission** case, which is the normal
> path for any correctly-behaving client.

## 4. Bug #2 — FIXED: router outages were reported as "your question is out of scope"

**Severity: medium (misleading failure surface + broken observability).**

`route_question` fail-closes to `route="out_of_domain"` on *any* router
failure (missing key, 429 storm, rotated model catalog). That routing is
correct. But `cannot_answer` then replied:

> "This request is outside the scope of the enterprise SEC financial
> intelligence database."

So a service-side failure was reported as a **verdict on the user's
question**. Live proof, fresh clone with no API key, asking a perfectly
in-domain question:

```
POST /query {"question":"What was Apple total net sales in Q4 2023?"}
→ {"answer":"This request is outside the scope of the enterprise SEC
   financial intelligence database.","outcome":"out_of_domain", ...}
```

while the server log said the truth:
`Router unavailable — FAIL-CLOSED to refusal: GROQ_API_KEY missing`.

This is the same class the project already fixed once for the audit stage
(`audit_unavailable` in `KNOWN_ISSUES.md`, 2026-09-16). I applied the same
pattern: a `router_unavailable` state marker (declared in
`MultiAgentState` + the channel-completeness contract test) and a refusal
text that names the true cause. `route` and `outcome` are unchanged, so
the chaos/failover contracts and the console's refused-banner are
untouched.

After the fix:

```
"⚠️ I could not classify this question: the routing stage is unavailable
 (the language model behind it is unreachable, unconfigured, or
 rate-limited). This is a service-side problem, not a verdict on your
 question — please retry shortly."
```

**Behaviour change — tell me if you want it reverted.** Validation is
still fail-closed; only the wording and the new state marker changed. A
follow-up worth considering (not done — it touches the outcome contract
and the frontend): emit `outcome="router_unavailable"` so `/metrics` shows
provider outages instead of a spike of "out_of_domain".

## 5. Also fixed (test hygiene)

`tests/test_failover.py::test_failover_registry_empty_when_unset` opened
`.env` unconditionally and **edits the developer's real `.env` in place**.
On a fresh clone (only `.env.example` is committed) it crashed with
`FileNotFoundError` — a traceback that looks like a code regression. It
now skips cleanly when `.env` is absent.

## 6. Found — all fixed in the same arc

1. **`/search` returned a bare 500 when the embedder was unavailable.**
   `{"error":"internal_error"}` with no hint that retrieval, not the
   query, was broken. **Fixed:** a named 503 for model/network failures
   ("the embedding model could not be loaded"), 500 otherwise.

2. **Boot smoke skipped the `openai_compatible` lane.** `lifespan`
   excluded exactly the lane whose catalogs rotate most (NIM / DeepSeek /
   self-hosted). **Fixed:** now probed, failures stay non-fatal, and the
   verdict is exposed at `/health.boot_smoke` so "which model is dead" no
   longer requires log access.

3. **Dead code after `return` in `db.py`** — an unreachable block
   referencing undefined names. **Fixed:** deleted (it was hiding six real
   F821 findings from the linter).

4. **`scripts/classify_canary.py` — `recall` undefined on the live exit
   path.** The canary crashed with `NameError` precisely when it had a
   verdict to report — and its exit code is what CI consumes.
   **Fixed:** bound from the same metrics dict the header already formats;
   verified by running it against a synthetic report (clean `EXIT 0: pass`).

5. **Frontend could not run behind any proxy/preview.** `api.js` hardcoded
   `http://localhost:8000`; the dev server bound localhost with no proxy
   and no `allowedHosts`. **Fixed:** dev proxies `/api` → the gateway
   (same-origin for the browser: no CORS, the `X-API-Key` header rides
   through), binds `0.0.0.0`, `allowedHosts: true`. Production unchanged —
   `VITE_API_BASE` still wins.

6. **Lint.** `ruff --select F821,F811,E9` now passes repo-wide (also fixed
   a duplicate `Response` import). The remaining F401/F841 noise (48 unused
   imports, 21 unused variables) is still there — not fixed, low value, but
   an `E9`/`F821` CI gate is worth adding since it caught two live bugs.

### Deliberately NOT changed

**Path A rejects possessives without an apostrophe** ("Metas revenue",
"Teslas EPS", "Apples and Teslas revenue") — they demote to the V1 fleet
and, with no provider key configured, refuse. This is **correct**: the
B.1.2 exact-match guard is fail-closed by design and fuzz-tested 42/42, and
with a key configured the fleet answers those normally. It only *looks*
broken in a key-less demo. Left as decided ground (AGENTS.md: check the
ADR before touching it).

## 6b. The demo that proves the moat (no API key needed)

`RAG_FACT_FASTPATH=1` serves ADR-017 Path A from `fact_rows` with **zero
LLM calls**, so the whole proof flow runs with no provider key at all:

```
POST /query {"question":"What was Apple's total net sales in Q4 2023?"}
→ "Apple reported total net sales of $89,498 million for Q4-2023 [1]."
  usage: {input: 0, output: 0, total: 0, llm_calls: 0}

GET /verify/{run_id}
→ verified: True, links 1/1, 1 claim, 1 evidence

GET /export/{run_id}
→ 10 KB bundle (certificate.json, verify_certificate.py, PUBLIC_KEY.pem, README.txt)

$ python verify_certificate.py          # on the extracted bundle, offline
→ PASS — chain verified offline (1/1 links ok, 0 citation issues)
→ exit code 0
```

That last line is the interview answer. It is also the 30-second demo:
ask → verify → PASS → download the bundle.

## 8. How to reproduce this review locally

The sandbox had no Docker, no apt network, and no HuggingFace/SEC/Groq
access, so I ran against a pip-installed Postgres:

```bash
pip install pgserver
pg_ctl -D /tmp/pgdata -l /tmp/pgdata/server.log \
  -o "-k /tmp/pgdata -c listen_addresses='' -p 5432" start

export DB_ADMIN_DATABASE_URL='postgresql://postgres@/postgres?host=/tmp/pgdata'
export DB_DATABASE_URL='postgresql://app_rag:ciruntimepw123@/postgres?host=/tmp/pgdata'
export APP_RAG_PASSWORD=ciruntimepw123
python scripts/bootstrap_roles.py     # runs all 7 migrations + creates app_rag
```

Two caveats specific to *this* sandbox, both environmental, not code bugs:

- **HuggingFace is blocked**, so `bge-small-en-v1.5` cannot download. I
  substituted a deterministic hash embedder for the DB/tenancy tests. The
  one remaining failure,
  `test_embedding_geometry_supports_near_exact_replay`, is purely a
  property of that substitute (assertion 2 needs two near-identical
  strings to embed 0.000x apart — impossible for a hash) and is expected
  to pass with the real model.
- **SEC EDGAR is blocked**, so `scripts/xbrl.py` cannot populate
  `xbrl_facts`. With the table empty, reconciliation is necessarily 0 and
  two integration tests failed — correctly. Supplying the published Q4-2023
  figures turned both green. The extraction itself was already right.
